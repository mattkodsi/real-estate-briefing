# Owner ticket CLI fallback

`python3 scripts/trd_session.py --issue-ticket [--domain bisnow.com]` now uses the operator's already-authenticated Supabase Management CLI when AUDIT_PIPELINE_SECRET is absent locally. It does not extract a login token or backend credential. A locally generated 256-bit ticket is hashed; only its hash and an allowlisted publisher enter a temporary SQL file calling public.issue_capture_ticket. The subprocess uses an argument array, fixed project ref, a 30-second timeout, captured output and no shell. Temporary files are removed on success, malformed acknowledgment, CLI failure and timeout. Success requires the observed CLI envelope's rows array to contain exactly one object with issued strictly true. Only the one-use ticket and normal expiry/domain guidance are printed. CLI stderr and arbitrary query response details are not echoed on failure.

The existing private-secret endpoint path remains preferred when configured. Direct --cookie writes still require the private secret; there is no anonymous or CLI direct-cookie fallback. The Management CLI path has the authority of the operator's existing project login and fails clearly when that authority or the RPC is unavailable. A response lost after successful issuance can leave an unused ticket until expiry; the script does not print an unconfirmed capability.

Five mocked tests pass: successful file/hash/argument/cleanup behavior, CLI errors and malformed responses, timeout cleanup, invalid domain rejection before subprocess, and continued private-secret endpoint behavior. Tests invoked no real query and issued no real tickets. CLI help was read, and root supplied the observed successful query response envelope for compatibility.
