# Information-quality guardrails

Implemented a read-only local CLI, `scripts/check_quality.py`, and seven behavioral tests. It accepts a local day path or YYYY-MM-DD under data/, plus optional --registry-dir for local terms/events/metrics registries. Default output lists constant-message errors/warnings and index locations, never subscriber bodies or headlines. --json provides the same safe findings as JSON. It never imports a network client, publishes, or edits input files.

Errors cover unambiguous structure/type problems: cards after briefs, featured briefs, card capacity, duplicate/missing IDs, invalid references, malformed typed amounts/statuses, a listed salePrice, nonboolean eligibility, missing eligible push copy, and overlength push microcopy. Warnings cover editorial review and missing legacy metadata: takeaway length/featured coherence, generic takeover actor wording, missing amount/status/transaction identity, source evidence, metric population, term alias collisions, and possible sentence fragments. Field presence never proves an official source, a financial claim, sentence completeness, ranking merit, actor identity or semantic term equivalence.

The appended corrective CLAUDE.md contract matches frontend valueType/transactionStatus fields and backend urgency/microcopy bounds, supersedes older conflicting notification examples, preserves uncertain event/metric evidence, and distinguishes source-backed receivedAt from summaryPublishedAt/enrichedAt/generatedAt.

Verification: `python3 -m unittest discover -s tests -p test_quality.py` passes seven tests, including a subprocess check that files remain byte-identical and output excludes a synthetic subscriber body. Tests were written and observed failing before implementation. No production data correction, publication, deployment, or external scheduled-prompt update was performed. Root owns narrow verified live corrections and workflow integration. Optional absent registry files are not inspected and are not represented as verified.
