# Independent publication review

Reviewed against baseline 2da606e: publication.py, push_data.py, both fillers, worker workflow, migration001, existing Edge fill-content and watchdog consumers, and publication tests. No production services or notifications were invoked.

Confirmed findings and fixes:

1. **P1 — fresh heartbeat triggered false failover.** The new writer emits fractional ISO timestamps; watchdog's strict seconds-only parser rejected every fresh pulse and scheduled local backfill plus a false notification. Reproduced with a freshly generated timestamp. Watchdog now uses ISO parsing, and started/running worker states count as a live heartbeat until they age out. The regression test intercepts both notifications and child processes and verifies neither is called.
2. **P2 — browser no-push results could not publish.** The browser stopped advancing generatedAt when writing an enriched local file. The new publisher correctly rejected that changed file as a same-timestamp replacement. Reproduced with a fabricated Bisnow URL cleanup. Browser and HTTP no-push paths now timestamp any changed local document.
3. **P2 — runtime budget could starve later articles.** Each bounded pass restarted from the first target, repeatedly spending its budget on the same blocked URLs. Both fillers now persist fillAttemptedAt through the narrow three-way merge, sort oldest attempts first, and stamp only articles actually attempted. Browser date order also prioritizes dates with oldest pending attempts, with older dates first on ties. Reproduced two consecutive passes visiting URL 0 twice before the fix and URLs 0 then 1 after it; the unattempted second story remains unstamped after pass one.
4. **P2 — Edge standby still read the retired shared primary pulse.** The Edge now reads the GitHub-specific publication_workers row, falling back to secrets only before an upgraded primary row exists. A failed primary is not hidden by a newer legacy standby pulse. Existing legacy writes remain for older consumers; an Edge-specific progress row is also recorded.

Verification after fixes: 19 publication Python tests and 3 heartbeat-policy Node tests pass; changed Python modules compile. The original 14 passing publication tests were rerun only after these modifications. The new tests first reproduced their respective failures. Existing isolated SQL rehearsal remains applicable because this review did not change migration001.

SQL review: compare-and-swap uses security-invoker execution, a fixed table allowlist, quoted identifiers and bound JSON inputs. The revision trigger writes only to a schema-qualified private-by-RLS revision table. Anonymous/authenticated revision reads are revoked; the accepted existing public content-write model remains unchanged. No additional concrete SQL permissions regression was identified.

Remaining boundaries: direct legacy content writers retain their original accepted permissions; they are not forced to use CAS. Editorial replacements require regenerated documents after timestamp conflicts. The ten-minute budget remains soft for an already in-flight network operation. Retry metadata updates the day revision even without new article text; it is operational attempt evidence, not evidence of newsletter arrival or successful enrichment. Actual GitHub container startup, Edge deployment and multi-worker production timing still need release verification.
